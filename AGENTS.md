# AGENTS.md

## Overview

This repository contains **aivillage** — a pixel-art village simulation game built with Python and Pygame. It features 19 AI-powered villagers with jobs, voices, and relationships that simulate real life using the actual clock, weather, and news. Dialogue is generated by LLMs through a provider-agnostic adapter system.

- **Version:** 0.4.19
- **Python:** 3.11–3.12 (not 3.13+)
- **Framework:** Pygame CE ≥ 2.5
- **Dependencies:** numpy, requests, feedparser, python-dotenv, pyttsx3

## Commands

- **Install dependencies:** `pip install -e ".[dev]"`
- **Run application:** `python run.py`
- **Run offline demo:** `python run.py --provider mock`
- **Run tests:** `python -m pytest -q`
- **Build desktop app:** `python build_app.py`
- **Build installers:** `python build_installer.py`

## Conventions

- **Python style:** Modern type hints (`list[str]`, `int | None`), snake_case for modules/functions, PascalCase for classes, UPPER_SNAKE_CASE for constants.
- **Imports:** Future imports first, then standard library, third-party, then local (relative within packages).
- **Docstrings:** Brief one-liners for modules and public functions.
- **Line length:** ~100 characters preferred.
- **Mixin pattern:** `VillageApp` uses mixin composition — each mixin handles one concern. Add new functionality as mixins, not by modifying existing ones.
- **Configuration:** Use `config.toml` (copy from `config.example.toml`). Access via `Config` class. Never hardcode configurable values.
- **Internationalization:** Use `self.i18n.get("key")` for UI strings. Locale files in `aivillage/locales/*.json`.

## Boundaries

- **`aivillage/app.py`** — Main application facade and mixin composition.
- **`aivillage/agents/`** — Villager AI logic (persona, needs, routines, memory, social).
- **`aivillage/llm/`** — LLM client abstraction and provider adapters.
- **`aivillage/news/`** — News pipeline (feeds, filters, dispatch, alerts).
- **`aivillage/reality/`** — Real-world integration (clock, weather, geo, calendar).
- **`aivillage/render/`** — Rendering, UI, HUD, dialogs, camera.
- **`aivillage/voice/`** — Text-to-speech (pyttsx3/SAPI5, Windows-only).
- **`aivillage/world/`** — World map, landmarks, pathfinding, geometry.
- **`aivillage/assets/`** — Fonts, sprites, SFX, palette.
- **`tests/`** — Pytest test suite (196 tests).

## Safety Rules

- **NEVER commit API keys** — use `.env` file (gitignored). Only store environment variable names, not keys.
- **NEVER commit save games** — they may contain personal data.
- **NEVER commit generated builds** — use CI/CD for builds.
- **Remote LLM gateways** should use HTTPS. Tokens are sent unencrypted over HTTP.
- **Windows SAPI voice** is Windows-only — handle gracefully on other platforms.

## Workflow

- Run relevant tests after edits: `python -m pytest -q`
- For bug fixes: write a reproducer test first, verify it fails, then fix.
- For new features: add tests proportional to complexity.
- Update documentation (PROGRESS.md, README.md) if behavior changes.
- Do not commit unless explicitly asked.
- Visual changes require manual testing or screenshots.
- LLM-related changes should be tested with `--provider mock`.

## Common Gotchas

- **Python version:** Must use 3.11 or 3.12. Python 3.13+ wheels are not available.
- **Pygame initialization:** Always call `pygame.init()` before other pygame calls.
- **LLM providers:** Mock provider is for testing only; real dialogue requires a configured provider.
- **Configuration precedence:** CLI args > setup screen > config.toml > defaults.
- **Mixin order:** Method Resolution Order (MRO) matters in `VillageApp` class definition.
- **Save slots:** Multiple save slots exist; autosave follows the last saved/loaded slot.
